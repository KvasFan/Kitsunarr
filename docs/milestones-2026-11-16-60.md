## Source selection and diagnostics

Interactive series, episode, season, pack and movie searches expose individual source
checkboxes. Changes apply with **Apply sources**; **All sources** restores the eligible
source set. These are request options, not changes to stored indexer settings. Selection
remains accessible while results load and when a search fails.

Native `GET /releases` and `GET /movies/{id}/releases` accept optional `indexerIds`, a CSV
of positive source IDs. Omission means all eligible sources; an explicit empty string means
none. Missing or disabled IDs and malformed selections return validation errors. IDs are
deduplicated and bounded to 64. Existing source tags, capabilities, back-off, rate limits,
search-mode switches and complete-series torrent restrictions still apply.

Search diagnostics list each queried source's outcome, elapsed milliseconds, returned
release count and generated first-page query plans. Plans include fallback tiers that may
not execute; their count is not an HTTP request count. Diagnostics omit request URLs,
credentials, headers and raw POST bodies. A whitelist selects useful query arguments, and
configured API keys, passkeys, usernames, cookies and URL credentials are redacted from
plans, reflected source errors and search warnings in logs.

**Titles considered** shows the titles and aliases available to the planner for the selected
season. Aliases belonging only to another scene season are excluded. Parsed/title-matched/
approved counts and the parsed title on unmatched releases distinguish retrieval, title
mapping and profile acceptance. Movie diagnostics show the title/year searches. These
changes explain existing mapping decisions; they do not silently broaden acceptance rules.

## Duration and supersession

Each source has a 35-second budget shared by capabilities, rate-limit waits, paging,
aliases and multiple queries. Other sources run concurrently, so one source timing out
still permits successful sources to return results. Native interactive requests, including
the v3 series adapter, have a 45-second overall deadline and return HTTP 504 on expiry.
The per-source budget also applies to automatic TV/movie searches using the shared runner.

The browser assigns a random `searchSession` to each search component. A new request with
the same session cancels the older server future (HTTP 409), while Dioxus cancels the old
resource and reqwest aborts its browser fetch. Changing applied sources or search targets
cannot publish stale results. The session registry holds at most 256 active named sessions;
leases clean up on completion, cancellation and timeout without deleting a newer lease.
Clients omitting `searchSession` still receive the duration limits. Navigating away aborts
the browser request; if the server has not detected that disconnect, its work remains
bounded by the source and request deadlines.

## Nyaa older-result investigation

Nyaa's upstream implementation explicitly limits RSS to its first result page in all three
search paths: Elasticsearch slices from zero, SQL uses a limit without an offset, and baked
SQL does the same. See
[`nyaa/search.py`](https://github.com/nyaadevs/nyaa/blob/master/nyaa/search.py)
and [`nyaa/views/main.py`](https://github.com/nyaadevs/nyaa/blob/master/nyaa/views/main.py).
Reviewed on 15 November 2026.

Adding `p`, `page` or `offset` would repeatedly fetch the same RSS results. Milestone 58 is
therefore completed as an investigation, with a visible Nyaa diagnostic explaining the
recent-result limit and suggesting a narrower title/episode query. This checkpoint does
not implement an HTML scraper or claim complete historical Nyaa coverage. Such a retrieval
adapter would need its own pagination, parsing and rate-limit verification.

## Verification

Automated regressions cover:

- Selection omission, empty selection, duplicates, malformed/missing/disabled IDs and no
  requests to an unselected source.
- Standard TV episode numbering, daily air dates, anime seasons and movie title/year queries.
- Season-specific aliases being included only for the matching season.
- Source diagnostic plans and known credential redaction, including percent-encoded URL credentials and
  cookie values.
- A fast source surviving another source's deadline; a budget shared across multiple source
  queries; the overall deadline; superseded HTTP requests returning 409 and cleaning up.
- Chromium source selection, re-enabling all sources, visible diagnostic plans, changing
  sources during a slow search, stale-result suppression, retries, empty results and partial
  or total failures. The existing profile group editor, library and zoom checks run too.

The first Chromium run exposed retained old results during retry: Dioxus keeps a resource's
previous value while fetching. The results component now explicitly checks its pending
state and displays loading instead. The corrected run repeats the full browser workflow.

## Existing local instance

The updated server and embedded UI are running at `http://127.0.0.1:8990`, managed by the
existing `kitsunarr-local-8990.service` user service. A consistent SQLite backup was made
before restarting it. An authenticated smoke test confirmed the new OpenAPI fields and
empty-source selection for both series and movies.

A live search for **Attack on Titan Season 3 Part 2**, season 1, selected only native Nyaa
(indexer 8): **291 releases**, **27 title/identifier matches**, one responding source and no
source failures in **26.60 seconds**. Diagnostics reported 13 planned queries and 24,077 ms
for the source work. No releases were approved by the existing profile; this checkpoint
preserves its acceptance settings. Verification did not grab or download media.

After deployment and the search, all seven quality profiles, series/movie paths and profile
assignments, every episode/movie file record, and indexer/download-client configurations
matched the baseline. Counts remained **80 series, 14 movies and 428 episode-file records**.
The backup and snapshots remain local with restricted permissions.
