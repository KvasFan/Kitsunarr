# Removal and deletion behaviour — milestones 77–80

Three more Sonarr behaviours were missing: unmonitoring episodes whose files were deleted,
excluding a removed series from import lists, and removing several series at once.

## Unmonitor deleted episodes (77)

Media management has Sonarr's **Unmonitor deleted episodes** switch
(`AutoUnmonitorPreviouslyDownloadedEpisodes`). It is off by default and migrated from Sonarr
and Tanukarr. Behaviour follows `EpisodeService.Handle(EpisodeFileDeletedEvent)`:

- A file deleted by hand from the series page unmonitors its episodes at once.
- A file found missing by a disk scan unmonitors its episodes when the scan ends, unless the
  same scan links them to another file, for example a file renamed outside Kitsunarr.
- Upgrades never unmonitor.
- Unmonitoring clears Jellyfin watched sync's ownership, as other explicit changes do.

## Import list exclusions on removal (78)

Removing a series can add an import list exclusion (Sonarr's `addImportListExclusion`), so
lists do not add it again. The exclusion uses the identity lists match: the series' own
TheTVDB, TMDB, AniList or MyAnimeList id, or else the first of those among its external ids. A
TVmaze-owned series is therefore excluded by its TheTVDB id. Excluding the same identity again
keeps one row. A series with none of these identities is removed without an exclusion, and a
warning is logged.

## Bulk removal (79)

`POST /api/v1/series/delete` and v3 `DELETE /api/v3/series/editor` remove several series. Each
is handled as a single removal would be, with optional folder deletion and exclusion. A failure
keeps that series and does not stop the others; the native route lists failures, and v3
answers 422 naming them. The series library's bulk bar has **Remove…**. The series page's
remove dialog gained "Prevent import lists from adding it again".
