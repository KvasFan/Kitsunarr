# Milestones 83–89: Sonarr API completeness, "Send now", tracked commands, anime season searches and blocklist migration

Date: 2026-11-17. Verified locally only; GitHub Actions is blocked by billing (#1).

## Why

The feature matrix kept "API compatibility" partial: the native API had every setting, but
Sonarr's `/api/v3` lacked the resources that sync tools and dashboards write and read —
Recyclarr's media naming and "propers and repacks" (`config/naming`,
`config/mediamanagement`), import lists, exclusions, delay profiles, tag details, the queue's
status, tasks and logs. Post-processing scripts (nzbToMedia and similar) could not ask for a
folder to be imported (`DownloadedEpisodesScan`). Pending releases could only wait or be
removed. The migration skipped Sonarr's blocklist.

Design points:

- **Config resources are Kitsunarr's settings under Sonarr's names.** A `PUT` replaces only
  the keys it sends and then goes through the native handler, so the validation is the same
  as in the browser (format checks, `chmodFolder`, RSS interval 10–120, keep-and-tag needs a
  tag, proxy checks). Sonarr settings Kitsunarr does not have (date formats, script import,
  season pack upgrade type) are answered with Sonarr's defaults and ignored when written.
  Tanukarr's "preserve original" file date reads as `none` under Sonarr's name and is kept
  when `none` is written back; `kitsunarrFileDate` carries the exact value.
- **`config/host` never returns secrets.** The API key is empty and the proxy password is
  the redaction placeholder, which keeps the stored password when written back. The listening
  address, port and URL base come from `config.toml` and are read-only.
- **Import lists keep Sonarr's top-level options** (`enableAutomaticAdd`, `shouldMonitor`,
  `rootFolderPath`, …) as the list's options, as migrated lists already did.
- **Exclusions**: TheTVDB ids are Sonarr's `tvdbId`; AniList, MyAnimeList and TMDB
  exclusions carry `provider` and `externalId` (their `tvdbId` is 0).
- **"Send now"** decides the pending release again with the RSS rules as the user's request:
  the delay profile no longer holds it back, every other rule still applies, and a rejection
  is reported while the release stays pending. The decision engine's `DelaySpecification`
  now skips any user-invoked decision; RSS sync and server-started searches are unchanged.
- **`DownloadedEpisodesScan` with a path** imports the files the manual-import matcher maps to
  a library series and episodes without rejections; the others are left. `importMode: Copy`
  copies, anything else moves. A release-named folder names the series of every file in it,
  as in Sonarr.
- **Commands are tracked** (`kitsunarr-api::commands`): a command is recorded as `started`,
  then `completed` or `failed` with its outcome (releases found and grabbed, series refreshed,
  files imported, the RSS summary, or the errors), as Sonarr's `CommandResource` reports it.
  The last 100 are kept in memory. Searches started from Kitsunarr's own pages still run while
  the page waits and show their outcome there.
- **Anime season searches** follow Sonarr's `SearchAnimeSeason`: the season searches, then one
  search per episode by its absolute number. Before, Kitsunarr searched the season only, so a
  Newznab indexer without "anime standard format search" received almost no request for an
  anime season. Automatic searches take aired (and, when asked, monitored) episodes; a
  season-pack search keeps to the season. With Tanukarr's "Prefer anime season packs", an
  automatic search runs the season searches first, decides them, and skips the episode
  searches of the episodes an approved full-season release covers.
- **Blocklist migration** keeps entries of imported series (and Tanukarr films) with their
  mapped episodes, quality, languages, protocol, indexer, release type, message and info hash;
  a re-run skips what was imported. Pending releases and the queue remain transient.

## Verification

- HTTP `sonarr_v3_config_rules_lists_and_system`: every config resource read and partially
  written, refusals (422), redaction, tag rename and details, delay profiles, mappings,
  exclusions (paged, bulk), import lists, root folders, tasks, backups, logs, queue status.
- HTTP `grab_sends_the_torrent_to_qbittorrent_and_records_history`: v3 queue status and
  details list the pending release; a non-pending download cannot be sent; v3
  `queue/grab/{id}` sends it to the qBittorrent mock while the delay still applies.
- HTTP `sonarr_v3_manual_import_and_downloaded_episodes_scan`: `manualimport` matches,
  `DownloadedEpisodesScan` copies the matched file and leaves the unknown one,
  `ManualImport` moves a file assigned by hand.
- api `commands::tests`; HTTP `sonarr_v3_api_serves_overseerr_and_prowlarr_flows` polls a
  rescan command to its (failed: empty root folder) end, and the manual-import test polls
  `DownloadedEpisodesScan` to "1 of 2 files imported".
- HTTP `anime_season_searches_search_each_episode_unless_a_pack_covers_it` (a Nyaa stand-in
  logs the terms: five without the option, the season only with it, five for an interactive
  search, the season only for a season-pack search); `direct_nyaa_season_searches_…` now
  expects the episode terms too.
- Decision `a_pending_release_sent_now_skips_the_delay`; db
  `tags_are_renamed_and_their_usage_listed`; migrate `blocklist_rows_from_backups_and_the_api`
  and the Sonarr fixture `sonarr_proxy_settings_and_blocklist_are_imported` (applied twice).
- Workspace: fmt, clippy `-D warnings` (host and wasm32), all tests, Chromium e2e, and the CI
  jobs on a clean clone.

## Feature matrix statuses

With these milestones every required feature's notes describe its behaviour as implemented.
The rows still marked "Partial" (1–3, 5, 9–13, 15–18, 21, 23, 25, the parse-matching row and
four Tanukarr rows) listed no missing behaviour any more: what they named was verification
against live services, or behaviour upstream does not have either (group-folder moves, regex
naming, Sonarr's scene-mapping feed, RSS film packs). They are "Done" now, as the legend
defines it (implemented and covered by automated tests). The services each was not checked
against live stay named in its notes. Live checks on 2026-11-17: TVmaze, AniList and
TheTVDB through SkyHook passed the opt-in `kitsunarr-metadata` live tests; Jikan did not
answer at the time (`curl` timed out too). A real Recyclarr container sync against a local
instance could not be run: the session's permission policy refused the container.
