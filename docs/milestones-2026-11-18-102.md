# Milestones 99–102: the second Tanukarr audit

Date: 2026-11-18. Verified locally only; GitHub Actions is blocked by billing (#1).

## Why

A second independent audit compared Tanukarr 0.1.5's code with Kitsunarr after milestones
93–98. It found 16 more gaps, of two kinds:

- **Interface.** Some features existed in the backend, but the interface never offered them:
  per-title editing, manual import choices and episode details, among others.
- **Ignored settings.** Some options were shown or stored but had no effect, such as "Delete
  empty folders". Some of Sonarr's decision rules were missing; without AlreadyImported, a
  release already imported could be grabbed again.

## What changed

| Milestone | Scope |
|---|---|
| 99 | Release profiles: air date restriction and excluded tags. Decision rules: AlreadyImported, DeletedEpisodeFile, SeasonPackOnly, BlockedIndexer and Pending (Kitsunarr now has 40 of Tanukarr's 41). Every media-management option now works, including script import, rejected extensions, permissions, season pack upgrades, episode title required and rescan after refresh. |
| 100 | Edit dialogs for series and movies. Bulk editor with a tag editor. Choices in manual import and "Override and grab". Episode details and the episode file editor. Bulk actions in the queue and the blocklist, including "Change category". |
| 101 | Naming options with live samples and the token picker. Collection settings and manual grouping when adding. Statistics page. Overview view and column chooser. Settings › UI. External links. Test parsing. Log files. Host and logging settings. Notification links. |
| 102 | Media covers served from a local cache. Custom formats on queue items and releases, and v5 release history. Translations of the new interface. |

## Design points

- **Overrides reach the import.** In "Override and grab", Sonarr records the chosen quality
  but reads the title again when importing. Kitsunarr keeps the choice through the import.
- **Old installations keep their free-space setting.** The free-space check now has two
  switches, one for grabbing and one for importing. A migration copies an installation's
  previous choice to both.
- **Host settings are written to `config.toml`.** They apply at the next start, and
  environment variables and command-line flags still take precedence. TLS is left to a
  reverse proxy.
- **Temporary rejections are kept, not dropped.** BlockedIndexer and Pending reject only
  temporarily, as delay profiles do, so the release stays pending.
