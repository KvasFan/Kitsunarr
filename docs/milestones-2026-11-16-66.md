# Reliability, custom formats and search usability — milestones 61–66

This follow-up builds on the search work completed at milestone 60. It includes the
[invalid negated regex correction](custom-format-regex-2026-11-16.md) from milestone 61.

## Guided custom formats

Settings › Custom formats now has controls for all eight evaluated Sonarr specification
types: release title/group regexes, language (including Original and except-language), source,
resolution, size bounds in GiB, indexer flags and release type. Every condition has a name,
negate/required switches and removal control. The editor explains the existing grouping
rules. Save is disabled for unnamed or empty formats and while saving.

The JSON editor remains available. Switching back requires valid JSON and preserves the
current draft when parsing fails. Unknown specification types and extension fields remain
in the draft. Migrated PascalCase field names are read case-insensitively; changing one
replaces all case variants of that field without discarding its other fields.

## Unsaved format tests

`POST /api/v1/customformats/test`, also exposed by the typed client and OpenAPI, accepts a
draft format and a sample release title. Optional inputs include file name, size, indexer
flags, quality, language and release-type overrides, and original language. Quality, subgroup, languages
and release type are detected from the title by default. The response reports the complete
format result, each condition's result after negation, detected values and compilation
warnings. Unknown conditions and invalid regexes remain unsatisfied even when negated.

This route uses the same compiled conditions and grouping as searches and naming; it does
not save settings, contact indexers or grab releases. The preview checks format membership,
not a quality profile's score or its complete acceptance decision. It has no library episode
context or indexer metadata unless explicitly supplied, so contextual search language
aggregation and episode mapping are outside the preview. Original-language placeholders
in dual-language titles are resolved using the supplied original language. Release type
can be overridden for a batch mapped to a complete anime season or a native movie's
single-episode feature, whose mapped type may differ from raw title parsing.

Tests require a nonempty title, at most 2048 characters per title/file name, 1–32 conditions,
at most 8192 serialized bytes per condition's fields, a nonnegative size and recognized
quality/language IDs. CPU work runs on a blocking worker and regex matching retains its
existing step/input budgets. Authentication and CSRF protection apply as for other native
settings routes. Editing a draft or its sample hides the previous preview, including a
response arriving after the edit.

## Release result filters

Interactive series, season, episode, pack and movie results can be narrowed with text and
All/Accepted/Rejected/Unmatched titles controls. Search words are case-insensitive and may
match across the title, subgroup, parsed title, indexer, quality, languages, custom-format
names, rejection messages and mapped episode labels. This makes a long anime result list
searchable by subgroup or an existing profile rejection without issuing another indexer
request. The visible/total count and a dedicated empty state distinguish filtering from
an empty source response. Clear filters restores the engine's original order. Changing a
filter clears any pending second-click grab confirmation.
