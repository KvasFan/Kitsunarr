## Behavior

Native movie notifications retain Sonarr/Tanukarr's one-feature payload: the movie is the
series and the feature is S01E01. Adding a movie through the catalogue API emits `SeriesAdd`.
Manual imports emit `Download`, including `isUpgrade`, the previous feature's metadata and
its recycle destination when available. They do not invent a download client or download id.
File deletion emits `EpisodeFileDelete` with `Manual` or `MissingFromDisk`; events are sent
after the file/history transaction commits. Existing per-connection triggers, upgrade switches
and tag scope apply. File payloads include stored languages, quality revision and source path;
automatic movie imports use the same stored-file builder. Manual import history now records
the incoming feature's quality and languages, including on upgrades.

The scheduled folder scan covers both libraries, continues past an unavailable title/root,
counts additions/removals/updates, emits change events and checks cancellation between titles.
The run fails if every title fails. An empty library is a successful no-op. Movie filesystem
guards and missing/empty-root protection remain in force.

Movie and series details provide **History** dialogs with event filtering and paging. Native
movie import, rename, deletion and restore event types are available in the shared history
selector. `GET /history` accepts `movieId`, `seriesId`, `episodeId` and `downloadId` alongside
its existing event/paging options. Filters combine with AND, invalid/nonpositive ids and
movie/episode-series combinations return 422, and unknown positive ids return an empty page.
Download ids match exactly without regard to ASCII case; SQL wildcard characters are literal.
Count and records use one read snapshot, with date/id ordering and indexes for episode and
case-insensitive download paging. Existing database/client history entry points remain valid.
