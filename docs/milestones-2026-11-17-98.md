# Milestones 93–98: the complete Sonarr API, full translations and Tanukarr parity

Date: 2026-11-17. Verified locally only; GitHub Actions is blocked by billing (#1).

## Why

Three things were still missing against Tanukarr 0.1.5:

- **The Sonarr API.** Kitsunarr served the part of `/api/v3` that tools call, and only the
  compression worker's callbacks under `/api/v5`.
- **Translations.** About 600 interface strings, the health messages and the task names were
  English only.
- **Tanukarr features.** An independent audit of Tanukarr's code (not its docs) found 16 features
  that Kitsunarr lacked or had only in part. It also found stale "not ported" notes in the
  technical decisions.

## Design points

- **v5 is built on v3.**
  - Each v5 handler calls the v3 handler and transforms the resource, so both versions read the same data the same way.
  - Where v5 differs, it gets its own code. For example, queue items are grouped per download and releases are nested.
  - Approximations are listed in technical-decisions §35. For example, `mediacover` redirects to the catalogue's image, and commands cannot be cancelled because they never queue.
- **Sign-in never goes through the Servarr relay.**
  - `auth.servarr.com` is registered to Sonarr and holds Sonarr's application secret, so Kitsunarr uses each service's own flow with the user's application.
  - The flows are Simkl and Plex PINs, Trakt's device code, and MyAnimeList and AniList authorization codes through Kitsunarr's callback.
- **Basic authentication is refused**, with Tanukarr's message, as Tanukarr does.
- **Allowed Hosts apply at once.** Tanukarr needs a restart.
- **Forwarded addresses are trusted only from trusted proxies.** This applies when deciding whether a request comes from a local address.
