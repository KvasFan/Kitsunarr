# Monitoring choices and library import — milestones 67–71

This follow-up closes two gaps against Sonarr found after milestone 66: Kitsunarr only knew
five of Sonarr's twelve monitoring choices and could not apply them to series already in the
library, and Sonarr's Library Import (adding titles from existing folders) was missing; the v3
root folder resource always reported no unmapped folders.

## Monitoring choices (67–68)

Every `MonitorTypes` value is accepted: all, future, missing, existing, first season, last
season (`lastSeason` and `latestSeason`), pilot, recent, monitor specials, unmonitor specials,
none and skip, by name or by Sonarr's number. One implementation, ported from Sonarr's
`EpisodeRepository.SetMonitored` and `EpisodeMonitoredService.SetEpisodeMonitoredStatus`, is
used everywhere:

- Every episode is set from the choice; specials change only with the two specials choices.
- Each season is monitored when it holds a monitored episode. The last season is also
  monitored for "all", and for "future" while the series continues or is upcoming. The first
  season stays unmonitored for the pilot alone.
- "None" also unmonitors the series; "skip" changes nothing.
- An explicit choice clears Jellyfin watched sync's unmonitor ownership, as manual edits do.
- Kitsunarr keeps one refinement: an episode without an air date that precedes an aired
  episode of its season counts as aired. Catalogues that lack old dates therefore do not turn
  old episodes into "future" or "recent" ones.

The choices apply when adding a title (the add page, v3 `addOptions.monitor`, import lists)
and to existing series: the series page's **Monitoring** dialog, the library's bulk
**Monitoring…** action (`POST /api/v1/series/bulk` with `monitor` and `monitorNewItems`) and
Sonarr's `POST /api/v3/seasonpass`. A v3 add without a choice keeps the request's seasons and
leaves specials unmonitored, as Sonarr's legacy path does; an explicit choice decides the
seasons. Films reject episode monitoring choices.

## Library import (69–70)

`GET /api/v1/rootfolders/{id}/unmapped` and the v3 `rootfolder` resource's `unmappedFolders`
list a root folder's folders that no title uses, as Sonarr's `GetUnmappedFolders` does:

- Folders are read as deep as the series (or, in a film root folder, film) folder format has
  separators.
- Sonarr's special folders (`lost+found`, `@eaDir`, `$RECYCLE.BIN`…) and the recycle bin are
  skipped. Folders containing a library title deeper down, such as Tanukarr collection
  folders, are skipped too.
- A v3 listing gives up on a root folder after five seconds, as Sonarr does.

Each folder carries the catalogue search it suggests: the id named by Sonarr/Radarr folder
tags (`[tvdbid-…]`, `{tvdb-…}`, `[tmdbid-…]`, `[imdbid-tt…]`) or its title without tags and
year, plus that year.

`AddTitleRequest.path` (and v3 `POST /api/v3/series/import`) adds a title with an existing
folder. The folder must be an existing directory strictly inside the chosen root folder,
without `..`, and must not hold, or be held by, another title. The folder is scanned in place
before the monitoring choice applies, so "existing" and "missing" see its files. Nothing is
moved or renamed. A v3 add with a path that does not exist yet keeps planning the folder from
the naming format, as before.

**Add media › Import existing folders** lists the unmapped folders of the chosen root folder
and matches them one at a time against the chosen catalogue. A folder's year picks among
results, and titles already in the library are offered but never chosen. Defaults cover the
monitoring choice, quality profile, series type and "search for missing". Each folder reports
its own result.
